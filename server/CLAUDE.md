# server/CLAUDE.md

Server package guidance. See [/CLAUDE.md](../CLAUDE.md) for project overview, monorepo map, request flow, and global code style.

## Commands

```bash
npm install               # installs deps; postinstall runs `prisma generate`
cp .env.example .env      # then set GEMINI_API_KEY and DATABASE_URL
npm run dev               # tsx watch — hot reload
npm run build             # tsc → dist/
npm run lint              # ESLint and Prettier
npm run typecheck         # tsc --noEmit
npm run db:up             # docker compose up -d (MariaDB on :3306)
npm run db:down           # docker compose down
npm run db:migrate        # prisma migrate dev — create + apply a migration
npm run db:deploy         # prisma migrate deploy — apply pending migrations (CI/prod)
npm run db:generate       # prisma generate — regenerate client after schema edits
npm run db:studio         # open Prisma Studio
npm run db:seed           # tsx prisma/seed.ts
npm run db:reset          # prisma migrate reset (DROPS the database)
```

After editing `server/prisma/schema.prisma`, run `npm run db:generate` in `server/` (or `npm install` — `postinstall` triggers it) before `tsx watch` will see new model types.

## Architecture

### Server internals

- **`src/helpers/EnvHelper.ts`** — Zod-validated env; process exits immediately if a required var is missing (`GEMINI_API_KEY`, `ETHERFUSE_API_KEY`, `RESEND_API_KEY`, `RESEND_EMAIL`, …). `ETHERFUSE_BASE_URL` defaults to the sandbox.
- **Security plugins** (`src/index.ts`) — `@fastify/helmet` (CSP disabled — the server only returns JSON + OAuth redirects, so there is no HTML to protect; CSP belongs on whatever serves the SPA's HTML. CORP is left at Helmet's `same-origin` default: the SPA reads API responses via CORS-mode `fetch` — avatars included, through `UserAvatar`'s fetch→blob — which never consults CORP) and `@fastify/rate-limit` (global 100 req/min per IP). The rate-limit `errorResponseBuilder` returns the standard `{ success: false, error }` body with a non-enumerable `statusCode` so the status is set without leaking into the body. `ban: 5` escalates a persistent offender from `429` (`RATE_LIMITED`) to `403` (`IP_BANNED`) after 5 over-limit hits, logged via `onBanReach`. The ban is in-memory (resets on cold start, per-machine, IP-keyed) so it is a deterrent, not a hard block. Per-route overrides via `config.rateLimit`: `POST /chat` 10/min (file parse + Gemini cost), `POST /auth/signup/request` 5/min, `POST /auth/signup/verify` 10/min. The health routes (`/` and `/health`) opt out with `config: { rateLimit: false }` so Fly.io's liveness probe can never be 429'd into a false "unhealthy" restart. Stores limits in-memory — fine for single-instance; swap to the Redis store before scaling to multi-instance.
- **`trustProxy: true`** (Fastify constructor) — required on Fly.io: requests arrive through Fly's edge proxy, so without it `request.ip` is the proxy address for every client and the per-IP rate limit collapses into one shared bucket. With it, `request.ip` resolves from `X-Forwarded-For` to the real client. Because `X-Forwarded-For` is client-spoofable under blanket `trustProxy: true` (a spoofed value would otherwise grant a fresh rate-limit bucket per request), the rate-limit `keyGenerator` keys on Fly's edge-stamped `Fly-Client-IP` header (which clients can't forge) and falls back to `request.ip` for local dev where there is no Fly proxy.
- **`src/helpers/FileHelper.ts`** — Dispatch by MIME type + extension. CSV → JSON string; XLSX/XLS → CSV string per sheet; PDF → raw text; TXT → utf-8 passthrough.
- **`src/services/ai-service.ts`** — Single `analyze(content, { token })` call. Sends the file content to Gemini and returns `{ payments }` (no longer returns `price`; `computePrice` was removed from the chat flow — the quote provides the accurate rate at confirmation time). Each payment is `{ id, amount, description }` where `amount` is the FIAT value from the file. Model is `gemini-3.1-flash-lite`. JSON is extracted with a regex fallback (`/\{[\s\S]*\}/`) in case the model adds surrounding text despite the system prompt. AI is instructed to:
  - Extract ONLY `{ amount, description }` per row — never addresses (the destination is provided separately and is global to the upload).
  - NEVER convert currencies — return amounts in the file's FIAT as-is. The expected FIAT is taken from `FIAT_BY_TOKEN[token]` (BRL for TESOURO); if the detected file currency doesn't match, return `{ payments: [] }`.
  - Treat bare numbers (e.g. `42,90` or `58.22`) as already-denominated in the expected FIAT for the selected token.
- **`src/services/chat-service.ts`** — Conversational AI agent. `processChat(input)` takes the full message history, available destinations, current payments, current chat destinations (allocations), and `userName`. Builds a context block injected into the Gemini system prompt each call — the block includes `userName` so the AI personalises messages. If `filePayments` are passed (from `/chat` route's file processing), they override AI-parsed payments. The context block enforces a strict rule for the `EXECUTE` action: its message is always overridden to `"Revise os pagamentos."` / `"Review your payments."` regardless of what the model produces. Returns `TChatResponse` with `action` field driving client state transitions. AI actions: `ADD_PAYMENTS`, `UPDATE_PAYMENTS`, `SET_DESTINATIONS`, `REQUEST_CONFIRMATION`, `EXECUTE`, `CREATE_DESTINATION`. The `CREATE_DESTINATION` action lets users register new destinations directly from the chat — AI collects name + PIX key, auto-detects PIX key type, normalises phone keys (adds "55" prefix), shows a summary, and on confirmation returns `newDestination: TCreateDestinationPayload`. Server validates `pixKeyType` against `PIX_KEY_TYPES` before passing through. Minimum payment total enforced client-side (`MINIMUM_PAYMENT_AMOUNT = 50 BRL`) before opening the review modal — if below, chat shows an error message instead of opening the modal.
- **`src/helpers/StellarExpertsHelper.ts`** — Generates Stellar Expert explorer URLs. `getTransactionUrl(hash)` → `https://stellar.expert/explorer/{network}/tx/{hash}`; `getAccountUrl(address)` → `https://stellar.expert/explorer/{network}/account/{address}`. Network (`testnet` | `public`) is determined once at module load from `EnvHelper.ETHERFUSE_API_KEY` (contains `"sand"` → testnet). Used by `payments-service.ts` (computes `addressUrl` in `mapPayment`) and `etherfuse-service.ts` (computes `addressUrl` in `createQuote`).
- **`src/routes/payments-route.ts`** — Payment CRUD. `POST /payments` creates an Etherfuse order then persists the full payment (items, destinations, messages, PIX data, encrypted sensitive fields) to the DB; returns `TCreatePaymentResponse`. `GET /payments` lists the user's payments with pagination/filters. `GET /payments/:id` fetches a single payment and syncs its status from Etherfuse if non-terminal. `POST /payments/:id/simulate` (sandbox only) triggers `simulateFiatReceived` for testing.
- **`src/routes/chat-route.ts`** — `POST /chat` requires `requireAuth`. Accepts multipart with `messages` (JSON string), `context` (JSON string with destinations/payments/allocations/language), and an optional `file`. If a file is present and valid, processes it through `FileHelper` + `analyze()` first, then passes results to `chat-service` along with `userName: request.user.name`. Returns `TChatResponse`.
- **`src/services/prices-service.ts`** — Pure I/O. `fetchUsdPerBrlPrice()` calls AwesomeAPI (`https://economia.awesomeapi.com.br/json/last/USD-BRL`); `fetchTesouroPerUsdcPrice()` queries Stellar Horizon orderbook. Both return `BigNumber` and throw typed `EErrorCode` (`RATE_FETCH_FAILED` / `ORDERBOOK_FETCH_FAILED`) on any failure — never falls back to 1:1.
- **`src/routes/upload-route.ts`** — Validates token (required); `address` is optional and no longer required in the upload flow (destination address is selected separately via DestinationsPage). File validation uses both MIME type AND extension (browsers sometimes send wrong MIME for `.xls`). 10 MB file-size limit is set in `@fastify/multipart` registration. Multipart fields must come BEFORE the file in the FormData stream (`token` first, `file` last) — `@fastify/multipart` only populates `data.fields` from parts that arrive before the file.
- **`src/services/etherfuse-service.ts`** — Thin wrapper around the Etherfuse Ramp REST API built on a pre-configured `axios` instance (same version `1.7.2` as the web client). Auth header is the raw key (no `Bearer` prefix), set on the axios instance once at module load. Generates partner-side UUIDs for `customerId` / `bankAccountId` / `quoteId` / `orderId`. Exposes `createOnboarding`, `getKycStatus`, `registerBankAccount`, `createQuote`, `createOrder`, `getOrder`, `simulateFiatReceived`. Network/HTTP errors are normalised to `EErrorCode.ETHERFUSE_REQUEST_FAILED`; 404 on order paths maps to `EErrorCode.ORDER_NOT_FOUND`. Quote `sourceAsset` is always `BRL`; `targetAsset` is `TESOURO:GCRYUGD5...`.
- **`src/services/chat-service.ts`** — Conversational AI agent. `processChat(input)` takes the full message history, available destinations, current payments, and allocations. Builds a context block injected into the Gemini system prompt each call. If `filePayments` are passed (from `/chat` route's file processing), they override AI-parsed payments. Returns `TChatResponse` with `action` field driving client state transitions.
- **`src/routes/chat-route.ts`** — `POST /chat` accepts multipart with `messages` (JSON string), `context` (JSON string with destinations/payments/allocations/language), and an optional `file`. If a file is present and valid, processes it through `FileHelper` + `analyze()` first, then passes results to `chat-service`. Returns `TChatResponse`.
- **`src/services/prices-service.ts`** — Pure I/O. `fetchUsdPerBrlPrice()` calls AwesomeAPI (`https://economia.awesomeapi.com.br/json/last/USD-BRL`); `fetchTesouroPerUsdcPrice()` queries Stellar Horizon orderbook. Both return `BigNumber` and throw typed `ErrorCode` (`RATE_FETCH_FAILED` / `ORDERBOOK_FETCH_FAILED`) on any failure — never falls back to 1:1. Called by `ai-service.ts` (`analyze`) and `balance-service.ts` to compute the FIAT↔TESOURO `price`. (There is no `upload-route` — file ingestion happens entirely inside `POST /chat`.)
- **`src/routes/health-route.ts`** — Registers `GET /` and `GET /health`, both returning `{ status: 'ok', service: 'fractapay-server' }`. Used by Fly.io health checks.
- **`src/services/balance-service.ts`** — Reads the on-chain TESOURO balance via a **read-only Soroban simulation** of the TESOURO Stellar Asset Contract's `balance(addr)` — no transaction is submitted and the account need not be funded. `Address.fromString` accepts both classic ed25519 `G…` accounts and smart-account contract `C…` addresses (the recipient is a passkey smart account). RPC + network + issuer are switched by the `isMainnet` constant (`src/constants` — `!ETHERFUSE_BASE_URL.includes('sand')`): mainnet vs testnet. A simulation error / missing trustline is treated as a `0` balance, not a failure. `getTesouroBalanceInBrl(address)` returns `TBalanceResult { token, balance, balanceInFiat }`, multiplying the balance by the same `tesouroPerUsdc × usdPerBrl` price as `ai-service`.
- **`src/routes/balance-route.ts`** — `GET /balance/:address` (public). Validates the address with `StellarHelper.isValidStellarDestination` (accepts `C…` smart accounts), returns `TBalanceResult` or `{ success: false, error }` (`502` with `ErrorCode.BALANCE_FETCH_FAILED` / `UNKNOWN`).
- **`src/services/etherfuse-service.ts`** — Thin wrapper around the Etherfuse Ramp REST API built on a pre-configured `axios` instance. Auth header is the raw key (no `Bearer` prefix), set on the axios instance once at module load. Generates partner-side UUIDs for `customerId` / `bankAccountId` / `quoteId` / `orderId`. Exposes `createOnboarding`, `createOrganization`, `submitKyc`, `getKycStatus`, `registerBankAccount`, `getCustomerBankAccountId`, `findCustomerByAddress`, `createQuote`, `createOrder`, `getOrder`, `simulateFiatReceived`. Network/HTTP errors are normalised to `ErrorCode.ETHERFUSE_REQUEST_FAILED`; 404 on order paths maps to `ErrorCode.ORDER_NOT_FOUND`. Quote `sourceAsset` is always `BRL`; `targetAsset` comes from a per-token `TOKEN_ASSET` map (`TESOURO:<issuer>`).
- **`src/services/etherfuse-customer-service.ts`** — DB-backed mapping of Stellar `address` → Etherfuse `customerId` (the `EtherfuseCustomer` model). `findEtherfuseCustomerByAddress(address)` and `upsertEtherfuseCustomer({ address, customerId, bankAccountId?, userId? })` (when `userId` is given, the upsert also mirrors `address` onto `user.address` in the same transaction). This persists the customer link so KYC/quote/order recovery survives restarts — distinct from the in-memory `etherfuse-webhook-store`.
- **`src/services/etherfuse-webhook-store.ts`** — In-memory cache (`Map`) of the most recent webhook event per `${event}:${id}` key (e.g. `order_updated:abc-123`). Records the event status, the full data payload and the originating timestamp. Used by the webhook receiver and available for future short-circuiting of polling.
- **`src/routes/onboarding-route.ts`** — `POST /onboarding` requires `requireAuth`. Starts Etherfuse KYC for a Stellar address.
- **`src/routes/customers-route.ts`** — `GET /customer/:address` requires `requireAuth`. Looks up existing Etherfuse customer/bank-account by Stellar address.
- **`src/routes/kyc-route.ts`** — `GET /kyc/:customerId/:address` requires `requireAuth`. Returns KYC status.
- **`src/routes/quotes-route.ts`** — `POST /quote` requires `requireAuth`. Creates a BRL→TESOURO price quote.
- **`src/routes/webhooks-route.ts`** — `POST /webhook` receives Etherfuse webhook events. Verifies the `X-Signature` header using HMAC-SHA256 over the JCS-canonicalized body (`canonicalize@1.x` package) with the base64-decoded `ETHERFUSE_WEBHOOK_SECRET`; uses `timingSafeEqual` for constant-time comparison. If secret is empty, verification is skipped (dev/sandbox). On `order_updated`, calls `updatePaymentById` to persist the new status (and optional `tokenAmount` / `transactionHash`) to the DB. Also records every event in `etherfuse-webhook-store` in-memory cache. **Webhook setup**: point the Etherfuse dashboard webhook URL at `<public-host>/webhook`.
- **Auth model is stateless JWT** (Bearer token, not cookies). The token is delivered to the SPA via an **authorization-code + PKCE exchange**, never in a URL fragment: the OAuth callback hands back a short-lived one-time `code` in a query param, the SPA POSTs `{ code, verifier }` to `/auth/exchange`, and the server signs the 7-day HS256 JWT there (so the 7-day clock starts at exchange, not at the Google callback). The SPA stores it in `localStorage` (`fractapay.token`) and sends it as `Authorization: Bearer …` on every API call. There is no server-side session store — `requireAuth` verifies the signature in-process. `@fastify/cookie` is registered both because `@fastify/oauth2` uses it for the `state`/PKCE round-trip with Google AND because the PKCE-exchange flow stashes the SPA's `code_challenge` in a signed `fractapay.pkce` cookie across the Google redirect (see auth-route + the root `onRequest` hook in `index.ts`). The cookie scheme for _app auth_ (signed `fractapay_session` + `Session` table) was removed.
- **`src/routes/etherfuse-route.ts`** — Proxies the Etherfuse flow so the API key never reaches the browser. Endpoints: `POST /etherfuse/onboarding`, `POST /etherfuse/organization` (creates an Etherfuse organization + wallets), `GET /etherfuse/customer/:address` (DB lookup → `TOnboardingResult` or `null`), `GET /etherfuse/kyc/:customerId/:address`, `POST /etherfuse/customer/:customerId/kyc` (submit `TKycIdentity`), `POST /etherfuse/bank-account`, `POST /etherfuse/quote`, `POST /etherfuse/order`, `GET /etherfuse/order/:orderId`, `POST /etherfuse/order/:orderId/simulate` (sandbox only), `POST /etherfuse/webhook` (receives `order_updated` / `kyc_updated` / etc. — validates the payload, logs through Fastify and stores in `etherfuse-webhook-store`). Every route validates its body/params with a per-route **Zod schema** (`safeParse` at the top of the handler) — schemas are module-level consts (`onboardingSchema`, `organizationSchema`, `addressParamsSchema`, `kycParamsSchema`, `submitKycSchema`, `bankAccountSchema`, `quoteSchema`, `orderSchema`, `orderIdParamsSchema`, `webhookSchema`). Addresses reuse a shared `addressSchema` (`z.string().refine(StellarHelper.isValidStellarDestination)`); `z.enum` guards `pixKeyType` / `token` / webhook `event` against the `PIX_KEY_TYPES` / `SUPPORTED_TOKENS` / `WEBHOOK_EVENTS` literal lists. A failed parse returns `{ success: false, error: ErrorCode }` (`INVALID_ADDRESS` for the address-only routes, `INVALID_PAYLOAD` otherwise). **Webhook setup**: point the Etherfuse dashboard's webhook URL at `<public-host>/etherfuse/webhook` so order/KYC state changes are pushed in real time. The in-memory `etherfuse-webhook-store` is fine for single-instance hackathon deployment; swap in Redis or a DB before scaling to multi-instance.
- **Auth model is stateless JWT** (Bearer token, not cookies). The token is delivered to the SPA via an **authorization-code + PKCE exchange**, never in a URL fragment: the OAuth callback hands back a short-lived one-time `code` in a query param, the SPA POSTs `{ code, verifier }` to `/auth/exchange`, and the server signs the 7-day HS256 JWT there (so the 7-day clock starts at exchange, not at the Google callback). The SPA stores it in `localStorage` (`fractapay.token`) and sends it as `Authorization: Bearer …` on every API call. There is no server-side session store — `requireAuth` verifies the signature in-process. `@fastify/cookie` is registered both because `@fastify/oauth2` uses it for the `state`/PKCE round-trip with Google AND because the PKCE-exchange flow stashes the SPA's `code_challenge` in a signed `fractapay.pkce` cookie across the Google redirect (see auth-route + the root `onRequest` hook in `index.ts`). The cookie scheme for _app auth_ (signed `fractapay_session` + `Session` table) was removed.
- **`src/hooks/require-auth.ts`** — Fastify `preHandler`s. `requireAuth` calls `request.jwtVerify<TJwtPayload>()` (payload `{ sub, email }`); on failure replies `401 UNAUTHORIZED`. On success it does a single `findUserById(payload.sub)` (canonical row, so avatar/name edits propagate) — replies `401 SESSION_EXPIRED` if the user is gone — then decorates `request.user` (TUser). `optionalAuth` does the same but never replies. The `FastifyJWT` interface is module-augmented here (`payload: TJwtPayload`, `user: TUser`) so `request.jwtVerify()` and `request.user` are typed — do NOT also declare `FastifyRequest { user }`, it collides (TS2717).
- **`@fastify/jwt` registration** (`src/index.ts`) pins `sign: { algorithm: 'HS256', iss: 'fractapay-server' }` and `verify: { algorithms: ['HS256'], allowedIss: 'fractapay-server', clockTolerance: 30 }`. Signing secret is `EnvHelper.SESSION_SECRET` (shared with the cookie plugin). CORS no longer sets `credentials: true`; `allowedHeaders` is explicit (`Content-Type`, `Authorization`, `Accept-Language`) — add to that list if a new request header is introduced.
- **`src/routes/auth-route.ts`** — `GET /auth/google` is registered automatically by `@fastify/oauth2` (as `startRedirectPath`) and kicks off the authorization-code + PKCE flow with Google. **A root-level `onRequest` hook in `index.ts`** (root because oauth2 owns `/auth/google` — an encapsulated plugin hook won't fire for it) reads the SPA's `?cc=<challenge>` and stashes it in a signed, httpOnly, SameSite=Lax `fractapay.pkce` cookie (`path: /auth`, 10-min maxAge) so the challenge survives the Google round-trip. `GET /auth/google/callback` exchanges the Google code for tokens, fetches userinfo, upserts the user, reads + unsigns the `fractapay.pkce` cookie (redirects to `WEB_LOGIN_FAILURE_URL` if absent), mints a one-time `code` via `createAuthCode({ userId, email, challenge })`, clears the cookie, sets `Cache-Control: no-store`, and redirects to `WEB_LOGIN_SUCCESS_URL?code=<code>` (query param, **not** a `#token` fragment — the JWT is never put in any URL). `POST /auth/exchange` (no auth) takes `TExchangePayload { code, verifier }`: `consumeAuthCode(code)` (single-use + TTL), `PkceHelper.verifyChallenge(verifier, challenge)`, then `reply.jwtSign` the 7-day JWT and return `TExchangeResult { success, token }`; bad shape → `400 INVALID_PAYLOAD`, bad/expired code or mismatched verifier → `400 INVALID_AUTH_CODE`. `POST /auth/logout` (uses `optionalAuth`) is a no-op success (stateless — the client wipes its own `localStorage`; there is nothing to revoke server-side). `GET /auth/me` requires `requireAuth` and returns `{ user: TUser }`. `POST /auth/onboarding` requires `requireAuth`, takes `TCompleteOnboardingPayload { companyName, address, passkeyCredentialId }`: replies `409 ONBOARDING_ALREADY_COMPLETED` if already onboarded, `400 INVALID_PAYLOAD` if any field is blank or `address` is not a valid contract address (`StellarHelper.isValidContractAddress` — the smart-account `C…`), else `markOnboardingCompleted(userId, { companyName, address, passkeyCredentialId })` stamps all three plus `onboardingCompletedAt = now` and returns the refreshed `{ user: TUser }`. **Email signup** is a two-step code flow (no password): `POST /auth/signup/request` (no auth) takes `TSignupRequestPayload { fullName, email }`, validates shape (`400 INVALID_PAYLOAD`), rejects an already-onboarded email (`409 EMAIL_ALREADY_REGISTERED`) or one linked to Google (`409 EMAIL_LINKED_TO_OAUTH`), then `createChallenge` + `sendVerificationCode` (language from `Accept-Language`) — `429 RESEND_TOO_SOON` (with `cooldownEndsAt`) inside the 60s cooldown, `502 EMAIL_SEND_FAILED` if Resend rejects; success returns `{ success, expiresAt, cooldownEndsAt }`. `POST /auth/signup/verify` (no auth) takes `TSignupVerifyPayload { email, code }` (6-digit), `consumeChallenge` (`400 VERIFICATION_EXPIRED` / `TOO_MANY_VERIFICATION_ATTEMPTS` / `INVALID_VERIFICATION_CODE`), re-checks the same OAuth/onboarded guards, then `upsertEmailVerifiedUser`, signs the 7-day JWT and returns `TSignupVerifyResult { success, token, user }`. `POST /auth/passkey/login` (no auth) takes `TPasskeyLoginPayload { address }` (must be a valid contract `C…`), looks up the user by `address` (`404 WALLET_NOT_REGISTERED`) and issues the JWT — **TODO**: it currently trusts the client-supplied address; the WebAuthn assertion is verified only in the browser, so add a server-side challenge/assertion check before issuing the session.
- **`src/services/auth-code-store.ts`** — In-memory `Map` of pending one-time auth codes for the PKCE exchange. `createAuthCode({ userId, email, challenge })` returns a `randomBytes(32).base64url` code with a 60s TTL; `consumeAuthCode(code)` deletes on read (single-use) and returns `null` if absent or expired. Single server instance + seconds-long TTL = restart-loss is harmless, no DB needed.
- **`src/services/email-verification-store.ts`** — Email signup verification challenges, backed by the `EmailVerificationChallenge` table (keyed on normalized email). `createChallenge({ email, fullName })` upserts a sha256-hashed 6-digit code (10-min TTL, 60s resend cooldown); `consumeChallenge({ email, code })` timing-safe-compares, caps at 5 attempts, and deletes on success/expiry/lockout. Both are `async`. DB-backed (unlike `auth-code-store`) because the 10-min TTL is a wide enough window that a mid-signup deploy/restart would otherwise lose a live user's code. A `setInterval` sweeps expired rows every 5 min.
- **`src/services/email-service.ts`** — Sends the signup verification code via [Resend](https://resend.com). Lazily constructs a `Resend` client from `RESEND_API_KEY` (and `from` = `<APP_NAME> <RESEND_EMAIL>`); `sendVerificationCode({ email, code, fullName, language })` renders localized HTML + text bodies via `i18next` (subject/greeting/body keys, `lng` = the caller's `TLanguage`) and throws on a Resend rejection so the route can map it to `EMAIL_SEND_FAILED`. If no client is configured it no-ops.
- **`src/helpers/PkceHelper.ts`** — `verifyChallenge(verifier, challenge)` computes `sha256(verifier)` base64url and compares to the stored challenge with `timingSafeEqual` (length-guarded). This is the S256 PKCE check for the SPA↔server exchange leg (distinct from oauth2's own PKCE with Google).

### Server DB layer

- **Schema** — `server/prisma/schema.prisma` uses `provider = "mysql"` (Prisma's MariaDB-compatible driver). `DATABASE_URL` is read from `server/.env` for both Prisma CLI and runtime. Note: `@db.Json` columns are stored as `LONGTEXT` on MariaDB.
- **Models** — `User` (id cuid, unique email, optional `emailVerified` / `name` / `avatarUrl` / `companyName` / `onboardingCompletedAt`, plus `address` (`@unique`, the passkey smart-account contract id) and `passkeyCredentialId` (`@db.Text`)); `OAuthAccount` (FK `userId`, `provider` + `providerAccountId` uniquely identifies the IdP identity — Google `sub` for now — `@@unique([provider, providerAccountId])` so the same Google account can't attach to two users; **no cached OAuth tokens** are stored); `EtherfuseCustomer` (`address` `@unique` → `customerId` + optional `bankAccountId` — the persisted wallet↔customer link, see `etherfuse-customer-service`); `EmailVerificationChallenge` (keyed on normalized `email` → sha256-hashed `code` + `expiresAt` / `cooldownEndsAt` / `attempts` / `fullName` — backs `email-verification-store`); `HealthCheck` (trivial table). There is no `Session` model — auth is stateless JWT (see Server internals).
- **Client** — `server/src/services/prisma-service.ts` exports a `PrismaClient` singleton cached on `globalThis` so `tsx watch` reloads don't open new connection pools, and re-exports everything from `@prisma/client` (`export * from '@prisma/client'`) so consumers can import model types (`User`, `OAuthAccount`, `EtherfuseCustomer`) and the `Prisma` namespace (for `Prisma.PrismaClientKnownRequestError` etc.) from the same file. User-row helpers live in `server/src/services/user-service.ts` (`findUserById`, `mapUserToTUser`, `upsertGoogleUser`, `markOnboardingCompleted`); `mapUserToTUser` now also surfaces `address` + `passkeyCredentialId`.
- **Local dev** — `docker compose up -d` in `server/` brings up `mariadb:11` on `:3306` (db `fractapay`, user/pass `fractapay`/`fractapay`). `npm run db:migrate` creates a timestamped migration; `npm run db:seed` runs `prisma/seed.ts`. `postinstall` runs `prisma generate`, so a fresh `npm install` always has a usable client.
- **Production (Fly.io)** — see the "Production deployment (Fly.io)" section in [/CLAUDE.md](../CLAUDE.md).

## Environment Variables

| File          | Variable                                    | Purpose                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server/.env` | `GEMINI_API_KEY`                            | Required — Google Gemini API                                                                                                                                                                                                                                                                                                                                                                                         |
| `server/.env` | `ETHERFUSE_API_KEY`                         | Required — Etherfuse Ramp API key (raw key, no `Bearer` prefix)                                                                                                                                                                                                                                                                                                                                                      |
| `server/.env` | `ETHERFUSE_BASE_URL`                        | Default `https://api.sand.etherfuse.com` (sandbox). Use `https://api.etherfuse.com` for production. the `isMainnet` constant (`src/constants`) is derived from whether this URL contains `sand` (`isMainnet = !…includes('sand')`); it also switches `balance-service`'s Soroban RPC, network passphrase, and TESOURO issuer between mainnet and testnet, and gates the sandbox-only auto-KYC in `etherfuse-service` |
| `server/.env` | `ETHERFUSE_WEBHOOK_SECRET`                  | Base64-encoded HMAC key returned when creating a webhook in the Etherfuse dashboard. Leave empty to skip signature verification (dev/sandbox)                                                                                                                                                                                                                                                                        |
| `server/.env` | `PORT`                                      | Default 3000                                                                                                                                                                                                                                                                                                                                                                                                         |
| `server/.env` | `CORS_ORIGIN`                               | Default `http://localhost:5173`. Comma-separated list of allowed origins for CORS                                                                                                                                                                                                                                                                                                                                    |
| `server/.env` | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Required — Google OAuth credentials registered with `@fastify/oauth2`                                                                                                                                                                                                                                                                                                                                                |
| `server/.env` | `OAUTH_CALLBACK_URL`                        | Default `http://localhost:3000/auth/google/callback`. Must match the redirect URI registered in Google Cloud Console                                                                                                                                                                                                                                                                                                 |
| `server/.env` | `WEB_BASE_URL`                              | Default `http://localhost:5173`. Base of the web app; default for the login redirect URLs below                                                                                                                                                                                                                                                                                                                      |
| `server/.env` | `WEB_LOGIN_SUCCESS_URL`                     | Default `${WEB_BASE_URL}`. Where `/auth/google/callback` redirects after a successful login. **Must include the SPA base path in prod** (e.g. `https://host/S37/`) — `exchangeCodeFromQuery`'s `isTrustedLanding()` only runs the PKCE code→token exchange when the landing pathname matches the SPA base path (`/S37` in prod, `/` in dev); a path mismatch makes login **silently fail**                           |
| `server/.env` | `WEB_LOGIN_FAILURE_URL`                     | Default `${WEB_BASE_URL}/?login=failed`. Redirect target on OAuth callback failure                                                                                                                                                                                                                                                                                                                                   |
| `server/.env` | `SESSION_SECRET`                            | Required, ≥32 chars. HS256 secret for `@fastify/jwt` (signs the Bearer token); also the `@fastify/cookie` secret for the OAuth state/PKCE cookie                                                                                                                                                                                                                                                                     |
| `server/.env` | `DATABASE_URL`                              | Required — MariaDB connection string; consumed by both Prisma CLI (`migrate`, `seed`, `studio`) and the runtime PrismaClient                                                                                                                                                                                                                                                                                         |
| `server/.env` | `RESEND_API_KEY`                            | Required — [Resend](https://resend.com) API key; `email-service` sends the signup verification code through it                                                                                                                                                                                                                                                                                                       |
| `server/.env` | `RESEND_EMAIL`                              | Required — verified sender address for the verification email (`from` = `<APP_NAME> <RESEND_EMAIL>`)                                                                                                                                                                                                                                                                                                                 |

## Code Style

Inherits global rules from [/CLAUDE.md](../CLAUDE.md). Server-specific:

- **TypeScript strict mode**.
- **Server imports**: no file extensions (e.g. `from './config'`) — `commonjs` module, TypeScript resolves `.ts` files automatically.
- **Arrow functions for routes**: use `export const Name = () => {}` for Fastify route handlers — never `export function`. Hooks use `export function useHook() {}` (regular function declaration).
