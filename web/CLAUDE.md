# web/CLAUDE.md

Web package guidance. See [/CLAUDE.md](../CLAUDE.md) for project overview, monorepo map, request flow, and global code style.

## Commands

```bash
npm install
cp .env.example .env      # set VITE_API_URL + the VITE_* smart-account vars
npm run dev               # Vite dev server
npm run build             # tsc + vite build
npm run lint              # ESLint and Prettier
npm run typecheck
```

## Architecture

### Web internals

- **Routing** — TanStack Router (`src/router/index.tsx`) defines a root route and an `id: 'auth'` pathless layout route (renders `RootLayout`, enforces session auth). Auth-protected routes: `/chat` (ChatPage), `/payments` (PaymentsListPage — order history), `/destinations` (DestinationsPage — recipients CRUD), `/profile` (ProfilePage — editable display name), `/payments/$id` (PaymentPage — receipt). `/` redirects to `/chat`. Public routes: `/login`. TypeScript type paths for auth-nested routes use the `/auth/` prefix (e.g. `useParams({ from: '/auth/payments/$id' })`); `to` in `navigate()` uses the URL path without prefix.
- **Auth & onboarding pages/hooks** — `LoginPage` renders `SignInButton` (sets `window.location.href = ${API_URL}/auth/google` to start OAuth), a biometric/passkey sign-in (`usePasskeyLoginMutation` → connect existing wallet → `/auth/passkey/login`; a dismissed prompt is swallowed, not surfaced), and a "Sign Up" button that navigates to `/onboarding?source=signup` to start email signup. `OnboardingPage` is a 3-step wizard driven by page-level consts `TOTAL_STEPS = 3`, `STEP_1_FIELDS` = fullName/email, `STEP_2_FIELDS` = companyName/cnpj (step 3 = passkey placeholder) — these live in `OnboardingPage.tsx`, not the schema; `onboarding-schema.ts` only defines `onboardingSchema` (fullName/email/companyName required, optional cnpj) for per-step `trigger()` validation. The page imports `APP_NAME` and `EErrorCode` from `fractapay-shared`. The **OAuth path** prefills identity from `useUserQuery` and skips step 1 (`skippedIdentityStep`). The **email-signup path** (`source === 'signup'`) verifies the email before company details: step-1 "Continue" calls `useSignupRequestMutation` (POST `/auth/signup/request` → emails a 6-digit code) and flips into an in-place verification sub-mode (not a separate dot — still "step 1") that takes the code via `useSignupVerifyMutation` (POST `/auth/signup/verify` → stores the JWT under `AUTH_TOKEN_STORAGE_KEY` + seeds the user query on success), with resend cooldown (`cooldownEndsAt`) and a change-email action; on success it advances to step 2. The final step submits only `companyName` via `useCompleteOnboardingMutation` (POST `/auth/onboarding`) — identity is already persisted (Google for OAuth, signup-verify for email). `useUserQuery` (`use-user-query.ts`) wraps `GET /auth/me` with a 5-min stale time; `useLogoutMutation` clears the token + stores.
- **Data store** — `src/hooks/use-data-store.ts` (Zustand, not persisted) holds `token: TToken` and `address: string` with `setToken` / `setAddress` actions. Used by `ChatPage` (sets token/address from user selection) and `ReviewModal` (reads token). DB payments are fetched via TanStack Query, not stored here.
- **Destinations state** — `src/hooks/use-destinations-store.ts` (Zustand + `persist` middleware, key `fractapay.destinations`) holds `destinations: TDestination[]` with actions `addDestination` / `updateDestination` / `deleteDestination`. Persisted to localStorage. Each destination has `id`, `name` (max 200 chars), `token`, `pixKey`, `pixKeyType`.
- **Chat state** — `src/hooks/use-chat-store.ts` (Zustand, not persisted) holds the active conversation: `messages: TChatMessage[]`, `payments: TPaymentItem[]`, `destinations: TChatDestination[]`, `summary: TPaymentSummaryItem[]`, `isProcessing: boolean`, `draftMessage: string`. No `price` field — the accurate rate comes from the Etherfuse quote at confirmation time. Reset on `execute` completion. `useChatMutation` (TanStack Query) posts to `POST /chat` with full history + context.
- **Payment queries** — `use-payments-query.ts` → `GET /payments` (list); `use-payment-query.ts` → `GET /payments/:id` (polls at 2s when status is `FUNDED` or `PROCESSING`, 5s otherwise, stops at terminal). `use-create-payment-mutation.ts` → `POST /payments` (creates payment + Etherfuse order atomically, updates query cache on success).
- **Breadcrumb store** — `src/hooks/use-breadcrumb-store.ts` exports `useBreadcrumbStore` (Zustand, not persisted) with `items: TBreadcrumbItem[]` and `setItems`. Pages call `useBreadcrumb(items)` (a helper hook in the same file) to register their breadcrumb on mount and clear it on unmount; the store reacts to the serialized items so re-renders are minimal. `Toolbar.tsx` reads from the store to display the current breadcrumb.
- **KYC state** — `src/hooks/use-kyc-store.ts` (Zustand + `persist` middleware, key `fractapay.kyc`) holds `customerId`, `bankAccountId`, `presignedUrl` keyed by address. Persistence is intentional: after the user finishes KYC and returns to the app, the customer/bank-account IDs survive a page reload so we don't restart onboarding.
- **Data fetching** — KYC hooks: `use-onboarding-mutation.ts` (POST /onboarding), `use-kyc-status-query.ts` (GET /kyc/:customerId/:address, polls until APPROVED/REJECTED), `use-quote-mutation.ts` (POST /quote). Payment creation: `use-create-payment-mutation.ts` (POST /payments). Payment polling: `use-payment-query.ts` (GET /payments/:id, polls every 2s when status is `FUNDED`/`PROCESSING` for fast offramp signing detection, 5s otherwise, stops at terminal).
- **Passkey smart account** — `src/hooks/use-smart-account.ts` wraps `smart-account-kit`'s `SmartAccountKit` (a lazy module-level singleton, configured from the `VITE_*` smart-account env via `EnvHelper`, `IndexedDBStorage` for credential persistence). `useSmartAccount()` returns memoized `createWallet(userName)` (deploys a passkey smart wallet — `autoSubmit`, optional `autoFund` when `VITE_NATIVE_TOKEN_CONTRACT` is set — and returns `{ contractId, credentialId }`), `connectWallet(contractId?)`, `connectExistingWallet()` (authenticate passkey → `discoverContractsByCredential` → connect; throws `NO_SMART_ACCOUNT` / `CONNECT_FAILED`), `rehydrate()`, and `signTransaction(xdr)` (parses a base64-encoded Stellar XDR envelope, signs every `invokeHostFunction` auth entry via `kit.signAuthEntry()` with the connected passkey, then broadcasts via `rpc.Server.sendTransaction` — returns the Stellar tx hash; used for offramp burn transactions). Mutation wrappers: `use-create-wallet-mutation.ts` (`createWallet`) and `use-connect-existing-wallet-mutation.ts` (`connectExistingWallet`) — both used by the onboarding wizard; `use-passkey-login-mutation.ts` connects an existing wallet, then POSTs `{ address: contractId }` to `/auth/passkey/login` and stores the returned JWT under `AUTH_TOKEN_STORAGE_KEY` (the no-OAuth, no-password return path on `LoginPage`); `use-sign-transactions-mutation.ts` signs all pending offramp burn transactions for a payment's destinations (filters `destination.transaction && !destination.completed`, runs in parallel via `Promise.allSettled`).
- **Form validation** — Zod schemas in `src/schemas/`: `destination-schema.ts` (`destinationSchema` — `name` max 200 / `pixKey` / `pixKeyType` / `token` for the DestinationModal), `onboarding-schema.ts` (`onboardingSchema` — `fullName` / `email` / `companyName` required, `cnpj` optional, for per-step `trigger()` validation), `payments-schema.ts` (`paymentEditSchema` — `amount` BigNumber > 0, `description` max 200).
- **Display formatting** — `StringHelper.formatCurrencyAmount(amount, token)` (in `shared/`) formats amounts as `R$ 152,56` for TESOURO using `Intl.NumberFormat` + `FIAT_SYMBOL_BY_TOKEN` post-processing. Display is fixed at 2 decimals; the stored value keeps full `STELLAR_DECIMALS` precision. Use `StringHelper.formatAmount` (accepts `string | number | BigNumber`) whenever a value is about to cross the network boundary (server↔web) — it caps at `STELLAR_DECIMALS` with `ROUND_DOWN`.
- **Reusable primitives** — `PageContainer.tsx` wraps `<main>` with the standard page layout (`max-w-5xl mx-auto px-4 py-8 space-y-6`); accepts optional `className` to override spacing. Used by all full-page routes. `Toolbar.tsx` is the fixed top bar (`h-14`, `z-30`, `lg:left-60`) — renders a hamburger button (hidden on `lg:`) that opens the mobile sidebar, plus `Breadcrumb` for the current page; `Breadcrumb.tsx` renders breadcrumb items from `useBreadcrumbStore` as an `<ol>` with `/` separators — linked items use TanStack `Link`, the last item is `aria-current="page"`; `Modal.tsx` wraps `@radix-ui/react-dialog`; `Accordion.tsx` wraps `@radix-ui/react-accordion`; `CountdownRing.tsx` renders the quote-expiry ring; `PixContent.tsx` renders QR + copy-and-paste PIX code; `Skeleton.tsx` renders animated loading placeholders; `RightPanel.tsx` is a thin wrapper over `SidebarPanel` (side=right, max-w-sm) — payments list or allocations detail; `UserAvatar.tsx` renders a user photo or initial-letter fallback; `ChatMessage.tsx` renders one chat bubble with avatar, file attachment, summary table, and timestamp — also shows the sender name above each bubble using `t('senderMe')` / `t('senderAssistant')` from the `chatMessage` i18n namespace; `ChatInput.tsx` renders the chat input area (suggestions chips, file preview, textarea, send button); `ChatPaymentsBar.tsx` renders the payments count bar and order-executed banner; `ChatThinking.tsx` renders the AI "…" typing indicator; `ChatSuggestions.tsx` renders the 4 example chips that fade out after the first user message; `DaySeparator.tsx` renders a date divider between messages from different days; `SidebarPanel.tsx` is the base for all sliding panels — handles overlay backdrop, slide animation, focus trap, Escape key, and `inert` management; calls `ScrollLockHelper.lock/unlock()` when the overlay is open to prevent body scroll and layout shift. Props: `open`, `onClose`, `ariaLabel`, `side` (`left|right`), `staticOnDesktop` (sticky on `lg:`, overlay on mobile), `panelClassName`, `header`, `children`, `footer`. `SidebarPanelHeader` is a convenience sub-component for the standard title+close header; `ChatSidebar.tsx` uses `SidebarPanel` (side=left, staticOnDesktop=true, w-64) — conversation list, new-conversation button with warning modal guard; `Sidebar.tsx` calls `ScrollLockHelper.lock/unlock()` when the mobile nav is open; the profile link shows an active state when on `/profile`; `EmptyState.tsx` renders the standard empty-state layout (icon + title + optional description + optional action) — used in PaymentsPage and DestinationsPage; `FeeIcon.tsx` — tooltip icon for fee labels; props: `label` (tooltip text), `className`; uses controlled open state; `ConversationWarningModal.tsx` (in `modals/`) warns before overwriting an unsaved new conversation — only shown when `activeConversationId === null` and user has sent messages.
- **Helpers** — `ScrollLockHelper.ts` (static class): `lock()` sets `overflow: hidden` and `paddingRight` equal to the current scrollbar width on `document.body` (prevents layout shift when a panel or sidebar opens); `unlock()` restores both. Used by `SidebarPanel.tsx` (overlay mode) and `Sidebar.tsx` (mobile nav open). `DestinationsHelper.ts` (static class, web-only): `formatPercentage(percentage)` returns `i18next.t('common:fullAllocation')` when `percentage === 100`, otherwise `"${percentage}%"`. Used in ChatPage, ReviewModal, PaymentPage destination lists. `ExternalLink.tsx` (component): reusable anchor with `Tooltip`, external-link icon, and consistent `text-primary` styling; props: `href`, `label` (tooltip + aria-label), `children`. Used for transaction hash and address links in PaymentPage and ReviewModal.
- **i18n** — `src/i18next/index.ts` initialises i18next with bundled JSON (`en-US` / `pt-BR`). Language toggle is in `Sidebar.tsx`. TypeScript-typed translations in `src/types/i18next.d.ts`. The common namespace includes `paymentTitle` / `paymentTitle_other` keys (pattern: `"{{date}} | {{amount}} | {{recipients}} recipient(s)"`) — used by `ChatPage`, `ChatSidebar`, and `PaymentPage` breadcrumbs.
- **Constants** — app-wide constants (`APP_NAME`, `FEE_PERCENTAGE`, `FEE_PERCENTAGE_VALUE`, `FEE_PERCENTAGE_DISPLAY`, token maps, file rules) live in `fractapay-shared` and are imported as `import { APP_NAME } from 'fractapay-shared'` (see [shared/CLAUDE.md](../shared/CLAUDE.md)) — do **not** redeclare them in web. Web-only constants live in `src/constants/index.ts`: `AUTH_TOKEN_STORAGE_KEY`, `PKCE_VERIFIER_STORAGE_KEY`, `BASE_PATH`, `LANGUAGE_NAMES`, `TOKEN_ICON_URL`, `PAYMENT_STATUS_CLASSES` (Tailwind badge classes per `TPaymentStatus`, used by `PaymentsPage` and `PaymentPage`), `EMPTY_VALUE`. The smart-account config (Soroban RPC / network passphrase / account WASM hash / WebAuthn verifier / native token contract) is **not** here — it lives in `src/helpers/EnvHelper.ts` as Zod-validated `VITE_*` env (the parse throws at module load on any missing value), read by `use-smart-account.ts`.
- **API client** — `src/services/server.ts` creates a single axios instance with `baseURL` from `VITE_API_URL`. A request interceptor injects `Accept-Language` and, when present, `Authorization: Bearer <localStorage['fractapay.token']>`. A response interceptor wipes the stored token on a `401` **only** when the request URL starts with `/auth/` or the response body's `error` is `UNAUTHORIZED` / `SESSION_EXPIRED` — so a proxied upstream 401 (e.g. Etherfuse) doesn't log the user out. No `withCredentials` (auth is Bearer, not cookies).
- **Auth token lifecycle (web)** — `SignInButton` starts login: it generates a PKCE `verifier` (`src/helpers/pkce.ts` — `generateVerifier` + `computeChallenge`, native `crypto.getRandomValues`/`crypto.subtle`), saves the verifier in `sessionStorage` (`PKCE_VERIFIER_STORAGE_KEY`), and navigates to `${API_URL}/auth/google?cc=<challenge>`. After OAuth, `exchangeCodeFromQuery()` (`src/helpers/auth-token.ts`) is `await`ed once from `src/index.tsx` at bootstrap **before** `createRoot`/render — the await matters because the exchange is a network POST and the token must be in `localStorage` before the first route guard fires `/auth/me` (the old fragment capture was synchronous; this is not). It reads `?code=` from the query, reads the verifier from sessionStorage, POSTs `{ code, verifier }` to `/auth/exchange`, stores the returned JWT under `AUTH_TOKEN_STORAGE_KEY` (`fractapay.token`), then always clears the verifier and strips the query via `replaceState`. Guarded against session-fixation — exchange is skipped (and query stripped) if a token already exists, the landing isn't trusted, or the verifier is missing: `isTrustedLanding()` (`src/helpers/auth-token.ts`) accepts the app root (`ROOT_PATHS`, local to that file, derived from `BASE_PATH` defined in `src/constants/index.ts` — `undefined` in dev so `ROOT_PATHS = {'/'}`; `'/S37'` in prod so `ROOT_PATHS = {'/S37', '/S37/'}`. a `document.referrer` whose origin === `VITE_API_URL` origin. The same `BASE_PATH` constant is consumed by the TanStack Router as `basepath` (`src/router/index.tsx`). `useLogoutMutation` POSTs `/auth/logout` (best-effort) then `localStorage.removeItem` the token and resets the stores.

## Code Style

Inherits global rules from [/CLAUDE.md](../CLAUDE.md). Web-specific:

- **TypeScript strict mode**.
- **Tailwind size shorthand**: when width and height are equal, use `size-*` instead of `w-* h-*` (e.g. `size-4` not `w-4 h-4`).
- **Accessibility**: always apply ARIA attributes where visible text alone is insufficient. Key patterns: `aria-label` on interactive elements whose purpose isn't clear from content (icon-only buttons, ambiguous controls); `aria-hidden="true"` on decorative elements (icons, illustrations); `alt` with meaningful text on informative images, `alt=""` on decorative ones; prefer semantic HTML over ARIA roles — only reach for `role` when no native element fits.
- **Input labels**: every `<input>` and `<textarea>` must have either an associated `<label>` (via `htmlFor`/`id`) or an `aria-label` attribute. Never render a bare input without one.
- **Semantic HTML**: always use the most specific semantic element available (`<main>`, `<header>`, `<nav>`, `<section>`, `<article>`, `<aside>`, `<footer>`, `<h1>`–`<h6>`, `<p>`, `<ul>`, `<ol>`, `<li>`, `<button>`, `<a>`, `<table>`, etc.). Reserve `<div>` and `<span>` exclusively for layout or styling containers that carry no semantic meaning.
- **Arrow functions for components**: use `export const Name = () => {}` — never `export function`. Hooks use `export function useHook() {}` (regular function declaration).
- **TanStack Query hook naming**: hooks wrapping `useQuery` must end with `Query` in the function name and `-query` in the file name (e.g. `useUsersQuery` in `use-users-query.ts`). Hooks wrapping `useMutation` must end with `Mutation` and `-mutation` (e.g. `useOrderMutation` in `use-order-mutation.ts`). This makes the data-fetching role unambiguous at a glance.
- **Responsive design**: all UI must work on mobile, tablet, and desktop. Use Tailwind responsive prefixes (`sm:`, `md:`, `lg:`, `xl:`) — mobile-first. No fixed pixel widths on layout containers; prefer `w-full`, `max-w-*`, or fluid units. Touch targets must be at least 44×44px.
- **Use reusable component primitives**: Never use raw `<button>` or `<input>` elements — always use the `Button` or `Input` components (or other established reusable primitives). Raw HTML interactive elements bypass variant, size, and accessibility defaults.
- **Unused translations and files**: After removing any `t('key')` call, run `npx i18next-cli status` inside `web/` to find orphaned keys and delete them from the locale JSON files. After removing an import or asset, verify nothing else references it before deleting the file.
- **Middle truncation for addresses**: always use `StringHelper.truncateMiddle()` to truncate blockchain addresses (e.g. `GABCD…WXYZ`). Never use CSS `truncate` or start/end ellipsis on addresses — both ends carry meaningful information.
- **Form element wrapping**: components that contain `<input>`, `<select>`, or other form controls must wrap them in a `<form>` element. Use `onSubmit={event => event.preventDefault()}` when form submission is handled programmatically. Reusable primitives (e.g. `Input.tsx`, `Select.tsx`) are excluded — the wrapping `<form>` belongs in the parent component.
- **Translation key cleanup**: when a `t('key')` call is removed from JSX/TSX, the key may still exist in the locale JSON files. After removing any `t()` call, run `npx i18next-cli status` inside `web/` to check for unused keys. Unused keys found there are safe to delete from `src/locales/{locale}/{namespace}.json`. TypeScript typed translations (`src/types/i18next.d.ts`) will catch compilation errors if a key is referenced in code but missing from the JSON.
- **Disabled element styles**: use only `disabled:opacity-50` for disabled interactive elements — never add `disabled:cursor-not-allowed` inline. Cursor behavior for disabled elements is managed globally in `src/assets/css/styles.css`. All disabled interactive elements must use the same opacity class to stay visually consistent.
